// app, RootGrantFlow.kt
package dev.superroot.ultraroot.ui
import dev.superroot.core.KsuRead
import dev.superroot.core.RootGrantPort

enum class GrantAction { GRANT, REVOKE }
data class GrantTarget(val uid: Int, val packageName: String)
sealed class GrantOutcome {
    data object Applied : GrantOutcome()
    data class Failed(val reason: String) : GrantOutcome()
}
data class AppGrantResult(val target: GrantTarget, val outcome: GrantOutcome)
sealed class GrantState {
    data object Idle : GrantState()
    data class Confirming(val action: GrantAction, val targets: List<GrantTarget>) : GrantState()
    data class Done(val action: GrantAction, val results: List<AppGrantResult>) : GrantState()
}
class RootGrantFlow(private val port: RootGrantPort) {
    var state: GrantState = GrantState.Idle
        private set
    fun request(action: GrantAction, targets: List<GrantTarget>): Boolean   // true só se aceito
    fun confirm(): Boolean
    fun cancel(): Boolean
    fun dismiss(): Boolean
}

Regras (cada uma tem teste):
R-a. request só é aceito em Idle e com targets não vazio. Em qualquer outro caso retorna false e o estado não muda.
R-b. request NÃO chama a porta. Ele só leva a Confirming(action, targets). Esta é a barreira de confirmação.
R-c. cancel só é aceito em Confirming: volta a Idle, sem chamar a porta.
R-d. confirm só é aceito em Confirming. Para cada alvo, na ordem da lista, chama port.grant(uid) (GRANT) ou port.revoke(uid) (REVOKE), uma única vez. Resultado por alvo: Applied se a resposta for Ok; Failed(reason) se for Unavailable(reason). Falha de um alvo NÃO interrompe os outros. Ao fim, estado vira Done(action, results), com um resultado por alvo, na mesma ordem, e cada resultado carrega o GrantTarget (packageName incluso).
R-e. confirm fora de Confirming (Idle ou Done) retorna false, sem chamar a porta. Isso impede repetir a escrita.
R-f. dismiss só é aceito em Done: volta a Idle.

Testes (nomes exatos, em RootGrantFlowTest.kt):
- requestDoesNotTouchThePort: request(GRANT, [A]) deixa state = Confirming e a lista de chamadas do fake vazia.
- requestWithoutTargetsIsRefused: request(GRANT, []) retorna false e state continua Idle.
- requestWhileConfirmingIsRefused: segundo request retorna false e não muda Confirming.
- cancelReturnsToIdleWithoutPortCalls.
- confirmGrantsEachTargetOnceInOrder: GRANT com uids 10123 e 10124 gera chamadas [grant 10123, grant 10124] e Done com dois Applied, na mesma ordem.
- confirmRevokeUsesRevokePort: REVOKE com uid 10123 gera [revoke 10123].
- failureOnOneTargetDoesNotStopTheOthers: grant(10123) devolve Unavailable("x"); grant(10124) devolve Ok. Resultados: Failed("x") para 10123 e Applied para 10124. Duas chamadas.
- confirmOutsideConfirmingIsRefused: confirm() em Idle retorna false, sem chamadas. Em Done, retorna false e não aumenta a lista de chamadas.
- dismissReturnsDoneToIdle, e dismiss fora de Done retorna false.
- resultCarriesPackageName: cada AppGrantResult.target.packageName igual ao do alvo de entrada.
